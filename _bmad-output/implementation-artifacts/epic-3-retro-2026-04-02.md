## Points d'attention

1. **Volume de review follow-ups élevé** — 5 items (3.1), 5 (3.3), 7 (3.4), 5 (3.6) = beaucoup d'allers-retours review/fix qui rallongent le cycle
2. **Zéro tests frontend automatisés** — toutes les validations UI passent par Aldo manuellement dans le navigateur, goulot d'étranglement majeur
3. **Régression silencieuse 3.7→3.8** — le changement silentAuth→auth dans routes.ts a cassé 7 tests generate.spec.ts, détecté seulement lors de la story suivante
4. **File List incomplète récurrente** — fichiers modifiés non documentés dans les stories 3.6 et 3.7, corrigé en review
5. **Temps limité d'Aldo** (études) — sessions de travail espacées, impact sur la vélocité globale

---

## Insights clés

> **Insight 1** — Les tests manuels sont le plus gros consommateur de temps d'Aldo. Automatiser les flux critiques avec Playwright libérera du temps pour le product/business.

> **Insight 2** — Les stories multi-agent (3.7 : sonnet + opus) indiquent que les stories complexes bénéficient d'un modèle plus capable. Utiliser opus pour les stories critiques.

> **Insight 3** — Le pivot architectural mid-epic (3.6 base64→URL) montre la capacité d'adaptation. Documenter ces décisions dans les Dev Notes est essentiel pour la continuité.

> **Insight 4** — Lancer la suite de tests complète AVANT chaque merge évite les régressions silencieuses entre stories.
